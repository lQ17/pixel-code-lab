# 后台管理后续开发路线

更新：2026-09-25。首版基线：`fb49694`。本文件记录首版之后的三轮开发任务；完成情况以《交接文档》和《开发记录》的实测记录为准。

状态：第一、二轮已实现并完成定向验收；第三轮尚未开始。第一轮已实现固定双栏与放大画布、已保存目标对照、二维实时笔触与坐标/平移、三维显式工具与落点状态、按维度恢复制作草稿、程序结果切换恢复、保存状态/重试/临时恢复。后续可根据真实制关反馈继续调整工具布局和操作手感；具体实测结果见《开发记录》。

## 第一轮：关卡编辑器体验与保存可靠性

目标：管理员能连续制作二维图案和带内部结构的三维模型，随时分辨编辑草稿、已保存目标和已应用内容。

1. 编辑工作台：左侧集中放基础信息、制作方式和工具；右侧提供已保存目标与当前结果的对照，以及可放大的编辑画布。切换 2D/3D、Python/积木/手动时保留各自草稿，不暗中覆盖。
2. 二维手动：按下拖动即显示笔迹，整笔作为一次撤销；经过格子连续补齐。显示坐标和颜色，提供明确的画笔、橡皮、吸管、平移操作、缩放与重置。键盘快捷键不能抢占输入框及代码编辑器。
3. 三维手动：明确的添加、染色、删除、吸管工具。立体视图显示下一步放置位置与可否落点，空场景可从所选 Z 层开始；切片网格同步，显示坐标和层号。编辑内部体素时不受观察剖切影响。操作手势与视角旋转分离。
4. 程序与手动：运行结果只有与当前代码或积木一致时能保存；复制结果到手动草稿前说明覆盖范围。源码修改、运行失败和停止均不能拿旧结果当新目标。
5. 保存：制作草稿防抖自动保存，并显示保存中、已保存、失败；写入失败后可重试和导出内存中的制作草稿。明确提示“目标有未保存修改”和“管理内容有未应用修改”；切换或离开编辑页时先落盘，失败时保护当前内容。
6. 结构：按编辑器画布、工具与草稿保存职责拆分过长的 `AdminPage`，不改变既有内容包和学生存档协议。

验收：实际创建二维与三维关卡，覆盖绘制、撤销/重做、程序结果复制、切换制作方式、刷新恢复、试做与应用。实测 1440×900 和 1180×768 布局；`npm run lint`、`npm run build` 与相关 Edge 行为测试通过。

## 第二轮：规模化章节与关卡编排

目标：约 30 个关卡分布在多个章节时，管理员仍能快速查找和调整。

1. 关卡库增加维度、归档与编排状态筛选，并显示所属大章/小节；支持复制自定义关卡为新 ID，形成独立进度。
2. 章节管理采用目录树和编辑面板，直接编辑名称、简介与顺序；小节可迁移到另一大章。删除或归档前展示受影响的关卡数量与去向。
3. 编排页固定“大章/小节树—当前小节关卡—关卡池”，支持搜索、维度筛选、批量加入、移出和跨小节移动。拖拽排序可加入，但按钮和键盘操作必须继续可用。
4. 移动、排序、改名不改变关卡 ID 和学生历史；删除小节不会级联删除关卡。列表操作后提供明确反馈和可撤回机会。

验收：用至少 30 个测试关卡操作筛选、批量编排、跨小节迁移、排序、归档与删除；刷新和重新应用后目录与进度关联保持正确。

## 第三轮：预览、应用与内容交付

目标：管理员能够在交付前确认学生实际体验，看到应用差异，并在导入或应用出错时恢复。

1. 独立试做复用真实学生工作台，支持 Python 与积木、目标和结果对照；试做代码、作品和进度与学生存档隔离。
2. 应用前比较管理草稿与当前应用内容，列出新增、修改、归档、移出、目录调整。保留最近一次应用版本并提供回退入口。
3. 导入前展示章节、小节、关卡数量与冲突/缺失引用；整包替换前自动备份当前管理草稿，校验或写入失败不损坏旧数据。
4. 学生目录显示当前位置和返回路径；“继续上次工作”在关卡归档、移出或内容包缺失时给出说明并引导返回目录。
5. 根据内容包体积和实际配额表现评估迁移 IndexedDB；若迁移，先实现旧 localStorage 数据无损读取、失败恢复和回退测试。

验收：完整走通“导入/编辑—试做—差异审阅—应用—学生挑战—回退”，覆盖存储失败和旧存档恢复。运行全量 Edge 回归与静态检查。
