# 成品关卡层级与布局愿景

记录：2026-09-24。本文记录用户确认的长期呈现目标，不是当前阶段的开发待办。当前功能与数据规则以《交接文档.md》为准；《总体规划.md》的用户原文保持不变。

## 核心层级

成品挑战内容按三级组织：

```text
章节（较大的主题与场景）
  └─ 小节（该章节内的学习主题）
       └─ 关卡（学生实际编程完成的具体任务，可有多关）
```

- 一个章节包含多个小节，一个小节包含多个具体关卡。章节用于承载主题场景和整体学习旅程；小节让学生看清当前学习内容；关卡提供目标图形、编程工作台与结果判定。
- 成品的挑战入口应先呈现章节，再进入小节与具体关卡。界面可参考扣叮的主题地图、可视化节点和清晰的进度层级，结合本项目的像素、体素与科幻视觉语言设计，不直接复制竞品素材。
- 章节、小节、关卡的名称、数量、课程顺序、解锁规则及具体交互尚未确定，后续根据课程内容单独设计。当前“全部关卡开放、不自动跳关”的规则继续适用于现有样例挑战。

## 当前样例与成品的关系

- 现有 2D 三关和 3D 七关只是验证编程、绘图、判定、存档及编辑方式的样例，不代表成品的章节、小节、关卡数量，也不应直接充当正式课程目录。
- 现有入口页平铺关卡卡片和“开始挑战”快捷按钮是样例阶段的界面。它们不决定成品的最终导航层级。
- 2D / 3D 是创作空间，积木 / Python / 后续语言是解题方式；它们与“章节 → 小节 → 关卡”的内容层级是不同维度。正式课程如何安排这些维度，留待课程设计时确定。
- 自由创作仍是独立玩法，不强行套入挑战关卡层级。

## 后续实现时的边界

- 先确定课程内容与稳定标识，再设计章节地图、小节页、关卡选择和逐级进度；插画素材按最终页面尺寸准备。
- 迁移导航或存档时保留现有样例关卡 ID、代码及历史通关记录，避免页面改版覆盖学生作品。
- 当前仅记录目标布局；本次不新增正式章节、小节、关卡、进度字段或解锁机制。
