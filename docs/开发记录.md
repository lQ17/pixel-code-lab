## 2026-09-17 · 编辑器、联动画布与持久化阶段

解析存档校验结构和关卡ID；损坏/不兼容时保留原文并暂停覆盖，用户明确确认后才恢复写入。读取失败或配额不足提示用户，不阻断执行。不持久化图形结果，刷新后重新运行。

## 2026-09-22 · 修复三维目标图与运行结果画布尺寸显示不一致

- 现象与定位：三维工作台右侧上方目标图与下方运行结果画布显示大小不一致（上方大、下方小，且下方模型偏上对齐）。根据第一性原理排查，`VoxelCanvas.tsx` 中三维投影缩放比例 `scale` 正比于 `Math.min(size.width, size.height)`，且两图共享视角与空间半径；问题根源为 DOM 结构与 CSS 规则不匹配导致下方画布高度被锁定在 280px：
  - 上方目标图直接作为 `.canvas-frame` 子元素，继承完整的自适应高度（约 380px）；
  - 下方运行结果为承载绝对定位的匹配率卡片，包裹了 `.voxel-result-wrap`；因父级 `.canvas-frame` 为普通块级元素而非 flex 容器，`.voxel-result-wrap` 缺少 `height: 100%` 规则，高度退化为 auto；
  - 内部绝对定位 canvas 不占流式高度，导致子元素 `.voxel-viewport` 依赖旧规则 `min-height: 280px` 支撑，下方 canvas 高度被固定在 280px。
- 修复方案（遵循 KISS 原则与 2D 对称架构）：
  - 在 `src/App.css` 中将 `.canvas-frame .voxel-result-wrap` 纳入 100% 宽高规则（对齐 `.canvas-frame .pixel-result-wrap`）；
  - 将 `.canvas-frame .voxel-viewport` 的 `min-height` 重置为 `0`，彻底消除 280px 锁定的影响。
