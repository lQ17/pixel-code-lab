# 网页版像素与体素编程游戏平台总体规划

## 一、项目定位

本项目拟开发一款运行在浏览器中的编程创作与学习平台。

用户通过编写程序，根据二维或三维坐标决定像素、体素的显示状态和颜色，从而生成：

* 2D 像素图像
* 3D 体素模型
* 后续可扩展的动态作品

项目核心体验为：

**编写程序 → 运行程序 → 立即看到图形结果 → 修改代码 → 再次运行。**

项目借鉴 Replicube 一类“通过代码生成图形”的玩法，但更强调编程教学和语言过渡，并计划长期支持：

* 积木编程
* Python
* C++

最终形成一个兼具游戏性、创作性和编程教学价值的平台。

---

# 二、项目目标

项目主要有四个目标。

### 1. 降低编程学习的抽象程度

传统编程学习中，学生经常只能看到：

```text
输入
↓
程序
↓
数字或文字输出
```

本项目希望将其变成：

```text
程序
↓
图形
↓
立即看到变化
```

让坐标、判断、循环、函数、数学表达式等知识拥有直观反馈。

---

### 2. 建立积木到代码的自然过渡

项目最终支持：

```text
积木
↓
Python
↓
C++
```

同一个图形、同一道关卡，可以使用不同语言实现。

这样学生学习新的语言时，不需要同时理解新的题目和新的知识背景，而只需要关注“同样的逻辑，在另一种语言中应该怎样表达”。

---

### 3. 同时支持学习和自由创作

平台不只提供固定题目。

整体分为两类玩法：

```text
挑战模式
+
自由创作模式
```

挑战模式用于学习和练习。

自由创作模式允许用户使用程序制作自己的像素画和体素作品。

---

### 4. 形成可长期扩展的平台

第一阶段只需要完成一个简单的 Python 编程小游戏。

但整体设计需要能够逐渐扩展为：

* 多语言
* 多关卡
* 创作平台
* 作品分享
* 用户成长体系
* 教师教学工具

---

# 三、目标用户

项目主要面向青少年编程学习者。

核心年龄段可覆盖：

**小学中高年级至初中阶段。**

根据学习水平，可以分为三个阶段。

### 初级用户

主要使用：

* 积木编程
* 2D 像素模式

重点学习：

* 坐标
* 顺序结构
* 条件判断
* 简单运算
* 变量

---

### 中级用户

主要使用：

* Python
* 2D + 3D

重点学习：

* 条件组合
* 循环
* 函数
* 数学表达式
* 二维与三维坐标
* 程序结构

---

### 进阶用户

主要使用：

* Python
* C++
* 复杂 3D 创作

进一步学习：

* 算法思想
* 代码优化
* 几何关系
* 空间逻辑
* 更复杂的程序设计

---

# 四、核心玩法

项目包含两个基础创作空间。

## 1. 2D Pixel 模式

整个画面由二维像素组成。

每个位置拥有：

```text
x
y
颜色
```

用户通过程序决定每个位置是否显示，以及显示什么颜色。

可以生成：

* 直线
* 矩形
* 圆形
* 图案
* 字符
* 像素人物
* 风景
* 图标

---

## 2. 3D Voxel 模式

整个空间由立方体体素组成。

每个位置拥有：

```text
x
y
z
颜色
```

用户通过程序决定当前位置是否存在方块以及方块颜色。

可以生成：

* 立方体
* 球体
* 圆柱
* 金字塔
* 房屋
* 树木
* 人物
* 建筑
* 抽象模型

---

# 五、主要游戏模式

## 1. 自由创作

用户进入空白画布或三维空间，自由编写程序。

主要用途：

* 实验代码
* 制作作品
* 测试想法
* 探索数学图形

自由模式不强调正确答案。

---

## 2. 挑战关卡

系统提供目标图形。

例如：

```text
请生成一个圆。

请生成棋盘格。

请生成一个空心立方体。

请生成一个球体。
```

用户通过程序尽可能还原目标。

系统判断结果是否正确。

---

## 3. 教学关卡

教学关卡除了目标图形，还会围绕具体编程知识设计。

例如：

```text
第1组
坐标

第2组
if 判断

第3组
and / or

第4组
循环

第5组
函数

第6组
数学表达式

第7组
二维转三维
```

让游戏本身成为一套渐进式编程课程。

---

## 4. 创意挑战

后续可以增加开放性题目。

例如：

> 用不超过三种颜色画一棵树。

> 制作一个机器人。

> 使用对称规律制作一个图案。

这种模式没有唯一答案，更强调创作。

---

# 六、多语言体系

项目长期支持三种编程方式。

## 第一层：积木编程

面向刚接触编程的学生。

提供类似 Scratch 的可视化积木。

主要包含：

* 判断
* 循环
* 变量
* 数学
* 逻辑
* 坐标
* 颜色
* 自定义功能

不需要完整复制 Scratch 的角色、舞台、声音等系统。

---

## 第二层：Python

Python 是项目的核心文本语言。

适合：

* 已掌握图形化编程的学生
* Python 初学者
* 中小学编程教学

Python 也是项目第一阶段优先开发的语言。

---

## 第三层：C++

面向更高阶段学生。

C++ 与 Python 使用相同的关卡和图形规则。

学生可以直接观察：

```text
同一个问题

积木怎么写
Python怎么写
C++怎么写
```

从而降低语言转换成本。

---

# 七、语言切换与教学衔接

长期目标是让同一作品支持不同语言实现。

例如一个圆：

```text
积木版本
↓
Python版本
↓
C++版本
```

平台可以进一步提供：

* 查看对应代码
* 对照不同语言写法
* 从积木转换到 Python
* 从 Python 学习 C++ 语法差异

这一功能将成为项目区别于普通编程小游戏的重要特点。

# 十四、第一版产品范围

第一版必须严格控制范围。

只解决：

> 用户能不能愉快地通过 Python 代码画出 2D 和 3D 图形？

因此第一版主要包含：

```text
Python代码编辑器

2D / 3D模式切换

运行代码

2D像素预览

3D体素预览

基本错误提示

视图缩放和旋转

代码自动保存

少量示例
```

只要这一闭环做顺，就可以继续扩展。

# 十六、项目核心架构思想

项目长期必须保证：

**编程语言和游戏本身相互独立。**

整体逻辑为：

```text
积木 ─┐
Python ┼─→ 图形数据 → 游戏系统 → 显示作品
C++   ─┘
```

即：

```text
语言负责“如何计算”

游戏负责“如何显示和判断”
```

这样才能不断增加新的语言和玩法，而不需要重写整个项目。

---

# 十七、项目主要特色

相较普通编程教学平台，本项目主要有以下特色。

### 1. 代码结果高度可视化

程序输出不是数字，而是直接生成图形和模型。

### 2. 同时支持 2D 与 3D

从二维坐标自然过渡到三维空间。

### 3. 多语言共用同一套题目

积木、Python、C++ 可以解决同一个问题。

### 4. 强调语言过渡

特别适合作为：

```text
图形化
↓
Python
↓
C++
```

的学习桥梁。

### 5. 同时具有游戏和创作属性

既可以做关卡，也可以自由制作作品。

### 6. 数学与编程结合

天然涉及：

* 坐标
* 几何
* 对称
* 距离
* 方程
* 空间关系

有利于形成编程、数学和创作结合的学习体验。

# 十九、项目成功标准

项目早期不以功能数量衡量成功。

最重要的标准是：

### 核心体验是否成立

用户是否能快速理解：

> “我的代码决定了这个图形长什么样。”

### 修改是否有即时反馈

用户改变一行代码后，可以很快看到图形变化。

### 是否有探索欲

用户是否愿意主动尝试：

```text
如果这里改成 5 会怎样？

如果加上 z 会怎样？

能不能画一个球？

能不能做一个人？
```

### 是否适合持续增加关卡

基础玩法是否足够支撑完整课程体系。

只要这几项成立，项目就值得继续扩大。

---

# 二十、总体发展路线

整个项目的发展路线可以概括为：

```text
Python图形实验工具
        ↓
2D / 3D编程小游戏
        ↓
编程挑战平台
        ↓
积木 + Python教学平台
        ↓
积木 + Python + C++语言过渡平台
        ↓
创作社区
        ↓
完整青少年编程学习平台
```

项目初期应保持简单，优先把：

**“编程 → 图形反馈”**

这一核心体验做到足够流畅和有趣。

之后所有功能都围绕这一核心逐步扩展。
