# 后台管理页面实施规划

日期：2026-09-24。状态：本地内容管理首版已实施；本文件保留原实施蓝图，当前行为与验证结果以《交接文档》《开发记录》为准。

## 1. 目标与首版边界

管理员可以制作二维像素或三维体素目标，将作品保存为关卡，再把关卡安排进“大章 → 小节 → 关卡”的目录中。学生继续通过 Python 或积木还原目标，按最终完整图形严格判定。

建议将“关卡分布编辑”命名为 **关卡编排**，与 **关卡库**、**章节管理**组成三个管理入口。

首版建议采用现有 React 应用内的本地内容管理工具：独立管理路由、独立数据存储、内容包导入导出及学生预览。当前没有服务端、数据库和管理员认证，隐藏入口或管理路由不构成权限控制；本地生效不会自动同步到其他电脑。真正的在线管理员后台需要另行确定部署、认证、数据库及发布方式，不默认在本轮扩展。

本方案默认覆盖 2D / 3D，复用 Python / 积木创作，新增管理员手动编辑。学生自由创作是否开放手动模式留待后续需求，首版只在管理端开放。暂不做图片自动转像素、模型导入、无限地图、更多颜色、课程解锁、班级和学习统计。

## 2. 已核对的项目基础

- 已阅读《交接文档》《总体规划》《项目规划书》《关卡层级与成品布局愿景》，并核对创作作品协议、关卡配置、路由、进度读取及三维投影代码。
- `src/engine/levels.ts` 的二维三关使用目标函数；各关 radius 为 5、4、10。`src/engine/voxel.ts` 的三维七关使用固定 ID、目标函数与可选示例。
- 二维自由创作为 21×21，三维为 17³；现有作品库以源码/积木结构为主，预览只是可选快照，不能直接当完整关卡协议。
- `src/navigation/route.ts`、`src/hooks/useProgress.ts`、`src/App.tsx`、`src/pages/StartPage.tsx` 均依赖静态关卡集合。只做管理表单，新增关卡仍无法进入挑战。
- 三维统一 Z-up，现有投影、面法线、悬停和剖切可复用，但手动放置需要补齐面命中、空场景工作平面和手势仲裁。
- 章节、小节尚未实现，也没有已经确定的正式课程目录。现有十个样例不能直接冒充正式课程内容。

## 3. 页面与操作流程

建议独立 Hash 路由：`#/admin/levels`、`#/admin/levels/:id`、`#/admin/chapters`、`#/admin/arrangement`、`#/admin/preview`。扩展现有路由解析，继续支持刷新与前进后退。

管理页沿用深色科幻风格，但信息管理使用清晰的列表与表单。关卡编辑仍采用左侧编辑、右侧上下对照；手动模式左侧放工具或二维切片，上方显示已保存目标，下方显示当前编辑结果，新建时上方显示空状态。提供放大当前编辑画布，不强制在小视口里放方块。

完整流程：

1. 新建关卡，选择 2D / 3D 与制作方式，填写名称和任务描述。
2. 使用程序生成，或直接手工绘制；也可复制现有创作作品到管理草稿。
3. 将当前有效结果保存为目标快照，生成缩略图。
4. 在独立预览会话中试做，确认坐标、颜色、显示与判定正确。
5. 在关卡编排中选择大章、小节与位置。
6. 保存草稿目录，校验后“应用到本机挑战”；需要交付到其他环境时导出内容包。

管理员试做必须使用独立进度，不污染学生代码、作品库或历史通关。

## 4. 关卡编辑器

### 4.1 基础信息与程序制作

关卡包含名称、任务描述、维度、空间尺寸、目标快照及制作来源。关卡归属由编排管理，编辑器可显示位置并提供跳转。

- 复用 Monaco、Blockly、PythonRunner 和渲染器，提取必要的共用工作台组件，不复制整个 App，也不做无关重构。
- 管理员使用独立草稿。从学生创作页/作品库“复制为关卡”时复制数据，不更改原作品和当前创作草稿。
- Python/积木只有成功运行且结果与当前源码、尺寸一致时，才能提交新的目标。运行失败、停止、修改后未运行的旧画面不能成为新目标。
- 草稿允许保留未完成代码或积木；未形成有效目标时不可应用到挑战。
- 管理源码、积木及制作备注与学生侧关卡数据分离。二维挑战不显示目标公式或参考答案；现有三维样例的示例行为保持，新关卡的制作源码不自动成为学生示例。
- 新建 2D 默认 21×21，3D 默认 17³。首版不新增任意尺寸编辑 UI；旧二维样例编辑保留各自尺寸，协议与渲染按记录的 radius 工作。

### 4.2 二维手动模式

首版必需工具：八种颜色、橡皮（颜色 0）、吸管、单格绘制、拖动连续绘制、撤销/重做、清空确认、坐标提示、缩放和平移。

一次按下至松开的笔画作为一次撤销操作；连续拖动补齐经过的格子，避免鼠标移动快时漏格。绘制与平移使用不同手势，并显示当前工具。按实际网格命中，不能按屏幕像素猜坐标。

框选、填充、镜像、直线等属于后续增强，首版不必加入。

### 4.3 三维手动模式

两种方式同时提供，共享同一体素数组与撤销栈：

**立体搭建**：选择颜色与“添加 / 染色 / 删除”工具。添加时使用命中体素的面法线，放置到相邻空格；染色修改命中格；删除置为 0。光标先显示半透明预览，越界或已占用时禁止放置并说明原因。

**逐层编辑**：首版按 Z 层选择，左侧显示当前层 XY 网格，可直接画、擦、吸色；三维预览同步更新。X 向右、Y 向上，Z 层号明确显示，可选显示邻层淡影。用于编辑内部、悬空或被遮挡的方块。

关键交互约定：

- 空模型必须有可命中的 XY 工作平面，默认 Z=0，可切到任意 Z 层放置第一块；操作范围仍为 -8～8，不强制模型从底层开始。
- 左键执行工具，右键拖动旋转、滚轮缩放；保留可见的视角按钮。避免沿用“左键拖动旋转”导致一次操作同时画图与旋转。
- 首版三维直接添加以单击为主，连续画线由切片网格承担，避免按住鼠标沿新表面无意堆出长柱。
- 复用同一投影与面深度关系；扩展命中结果为体素坐标、面法线和交点。普通视图、俯视、旋转和缩放后均须验证。
- 剖切只改变观察。内部编辑优先走切片；剖切视图的放置预览必须检查完整数据的占用，不能覆盖被隐藏的体素。
- 手工修改不经过 Python 执行，每次只改变格子数据；保存与判定使用完整模型，不使用剖切后的可见模型。

### 4.4 程序与手动制作之间的关系

程序可以“将成功结果复制到手动草稿”后继续修饰。原源码和原程序草稿保留；手动修改不会反向生成公式、积木或冒充源码运行结果。

两种制作方式维护独立草稿。目标记录明确的当前来源，保存时只从所选来源取快照。已有手动草稿被新运行结果替换前提示；简单切换页签不得覆盖任何数据。

二维 move_origin 的结果按既有数组位置保存；目标采用默认世界坐标。制作时的原点偏移可以作为来源元数据保存，但不能再把目标平移一次，也不要求学生使用相同原点。

## 5. 关卡编排与章节管理

### 5.1 关卡编排

左侧为“大章 → 小节”树，右侧为当前小节的有序关卡列表，另有未编排关卡池。支持搜索、按维度筛选、添加、移出、上移/下移、移动到另一小节；拖拽可作为增强，不能是唯一操作方式。

首版建议一关最多属于一个小节，允许暂未编排。移动保留关卡 ID 与进度；“移出小节”只解除归属，不删除关卡。“复制关卡”生成新 ID 并拥有独立进度。如果未来需要同一关多处复用，再扩展编排关联实体。

大章和小节可以混排 2D / 3D，维度属于关卡属性，不再以维度创建两套内容树。学生仍可按维度筛选。

### 5.2 大章与小节

支持新建、重命名、修改简介、排序、删除，小节可移动到另一大章。名称不能作为 ID，排序也不能改变 ID。

删除规则：

- 空小节、空大章：确认后删除。
- 有关卡的小节：先选择迁移到其他小节或全部移入未编排池，再删除小节；不级联删除关卡。
- 有小节的大章：要求先迁移或处理小节，并提示影响数量；首版不提供一键级联删除整章内容。
- 删除/停用关卡：先列出归属与影响，首版优先使用归档。应用到学生端后不再开放入口，历史代码与通关保留。

首次进入管理工具时提供空正式目录；十个内置关卡显示为“内置样例”，保留学生原入口。管理员可主动将样例编入目录；迁移不更改其 ID。

## 6. 数据与保存设计

### 6.1 建议模型

| 实体 | 核心字段 |
| --- | --- |
| Chapter | id、title、description、order |
| Section | id、chapterId、title、description、order |
| Level | id、title、description、mode、radius、targetColors、targetRevision、source、archived |
| Placement | levelId、sectionId、order；levelId 唯一 |
| AuthoringSource | python / blocks / manual；源码或结构、制作元数据 |
| ContentPackage | format、version、chapters、sections、levels、placements |

目标使用固定顺序的颜色快照，可用 0～8 字符串紧凑保存，读取后转换为数值数组。长度必须与空间尺寸一致；2D 按 y 降序、x 升序，3D 按 z 升序、y 降序、x 升序。缩略图从快照生成，不是判定依据。

已发布目标变化增加 targetRevision。首版仍保留历史通关，不自动撤销；运行中的结果绑定启动时的关卡 ID、目标版本和任务编号，目标更新时取消旧任务。改名、排序、移动不增加目标版本。已使用关卡不直接改变维度/尺寸，需要另存新关卡。

### 6.2 存储与本地应用

- 管理草稿、应用版本、学生进度分开存储；不把管理数据塞入 `pixel-code-lab.progress`。
- 建议管理内容用 IndexedDB，草稿与应用快照以事务保存；学生原存档保持现有机制。用 repository 接口隔离存储，后续可替换为服务端接口。
- 有防抖草稿保存、保存状态、离开保护。提交和应用均先校验、成功落盘后再更新界面；配额或读写错误时保留编辑内容并允许导出，不假报成功。
- “应用到本机挑战”生成完整、校验通过的只读快照；学生端读取该快照，不读取实时编辑草稿。未编排/归档内容不进入正式目录。
- 提供编辑备份包与学生内容包两种导出：前者保留制作源码，后者剔除管理员制作来源。导入先预检，列出新增、冲突、缺失引用；首版可采用整包替换管理数据并先备份，不做隐式覆盖合并，不执行导入源码。
- 对版本、尺寸、颜色、重复 ID、引用、层级关系、排序、字符串及整体大小设置显式限制。导入失败不写入任何数据。
- 正式静态发布可由开发流程将学生内容包放入构建资源并部署；浏览器管理页不能直接修改项目文件或远端部署。本轮不自动发布。

### 6.3 动态关卡与存档兼容

新增统一关卡目录查询层，将内置关卡转换为同一种只读快照描述，与自定义内容共同供路由、工作台、判定与列表消费。保留现有示例生成入口，不把创作参考 ID 与所有动态挑战 ID 混为一谈。

存档解析不能继续仅遍历静态关卡 ID：合法但暂未安装、已归档或缺失的关卡记录应保留，不能判整份存档损坏，也不能保存时丢弃。字段类型与资源限制仍严格校验。缺失关卡链接显示“当前内容不可用”和返回入口，不偷偷切到另一关或删除其草稿。

优先保持 schemaVersion=1 的向后兼容读取；若实施中确需升级，必须先定义无损迁移及失败恢复，不能简单清空旧存档。旧 2D 三关、3D 七关 ID、源码、积木、作品库与通关记录全部保留。

## 7. 学生端的最小接入

为了验证编排真正生效，首版至少增加简单的“大章列表 → 小节列表 → 关卡列表”，无需本轮制作场景插画或地图动画。自由创作保持独立入口。

旧样例入口在没有正式内容时保持可用；有正式目录后保留单独样例入口，避免未编排的内置关卡消失。正式目录全部开放，不增加解锁、不自动跳关。挑战工作台继续左侧编辑、右侧上下对照，匹配完整目标，不显示错误格定位。

“继续上次工作”优先恢复原关卡；不可用时提示并返回目录。阶段内同时核对开始挑战按钮、进度计数和浏览器前进后退，避免只替换卡片而遗留静态 ID 逻辑。

## 8. 实施顺序与交付点

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| A 数据基础 | 内容协议、校验、repository、内置关卡适配、动态 ID 兼容 | 内置十关与旧存档无损；自定义快照可进入独立预览 |
| B 管理骨架 | 管理路由、关卡库、章节 CRUD、关卡编排 | 可建立目录、移动排序、处理删除并刷新恢复 |
| C 程序制关 | 复用创作能力、复制作品、生成目标、独立试做 | Python/积木生成的 2D/3D 目标可保存并严格判定 |
| D 手动编辑 | 2D 画笔、3D 面放置与切片、撤销重做、模式草稿保护 | 从空场景及程序结果均可完成手工关卡 |
| E 接入与交付 | 本机应用、内容包、学生三级目录、兼容回归 | 制作 → 编排 → 应用 → 学生挑战全流程闭环 |

建议按阶段实施和验收，但完整需求包含 A～E，不能把仅有静态后台表单当作完成。

建议新增 `src/admin/`、`src/engine/content/` 与独立存储模块；具体文件按职责拆分。现有重点改动入口为 App、route、StartPage、useProgress 以及画布命中逻辑，避免继续把所有管理状态堆入 App。

## 9. 验收要求

1. 二维、三维分别使用 Python、积木和手动方式创建关卡，刷新后目标与来源完整恢复；失败运行不会替换目标。
2. 程序结果转手动后修改，不改源码；切换来源、打开其他作品和离开页面保护双方草稿。
3. 三维从空场景放第一块、六个方向邻面添加、染色、删除、越界阻止、内部切片编辑均正确；旋转/俯视/缩放/剖切后预览与落点一致。
4. 撤销/重做覆盖完整笔画、添加/删除、清空；旋转和观察剖切不进入编辑撤销栈。
5. 大章、小节的新增修改删除、迁移排序正确；移动关卡 ID 不变，移出不删除，有内容的容器不会静默级联删除。
6. 草稿修改不影响应用版本；应用后学生按三级目录进入正确关卡，独立预览不写学生进度。
7. 非法颜色、长度、版本、重复 ID、悬空引用、超大文件和存储失败不破坏旧数据；未知/归档关卡的学生代码与历史通关保留。
8. 旧作品文件、旧进度、二维原点、三维 Z-up、执行取消/超时/过期结果隔离继续正常。
9. 每阶段运行对应行为测试；最终运行 `npm run lint`、`npm run build`、Windows Edge `npm test`。新增内容协议、管理 CRUD、手动编辑、编排应用和迁移测试，复用现有测试基础。
10. 修改 UI 后查看真实渲染，至少覆盖 1440×900 与 1180×768；手动模式必须实际验证操作，不能只凭截图判断放置正确。

实施后更新《开发记录》《交接文档》与规划书状态说明，保留《总体规划》原文。未经用户新指示不提交、推送或部署。

## 10. 给实施模型的任务说明

先阅读 AGENTS.md、docs/交接文档.md 和本方案，按 A～E 完成管理工具与学生最小接入。采用本地内容管理首版，不自行增加账号、服务器、课程解锁或正式地图设计。把目标快照作为统一判定数据，保护旧存档和创作草稿；完整实现三维直接放置及切片编辑，不能用只能看不能编辑的预览代替。阶段性说明实测结果与未完成部分，不自动执行 Git 操作。若用户明确要求多人在线管理，应先将存储与发布部分改为对应的服务端实施方案。
